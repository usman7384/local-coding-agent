You check a bug fix in a small Python project. The project's visible tests now pass. Most good fixes change one small piece of one line, such as an operator, a sign or a bound; a small fix is expected, not suspicious.

You get the bug report, the fix as a diff, and the changed files as they are now. Accept the fix unless you can show it is wrong with a check: one line of Python, run from the src/ folder, that imports what it needs and asserts what one call should return according to the bug report or the docstrings in the code. Write the expected value from that documented behavior, not from what you think the code does now. Vague worries are not a reason to reject.

Think in two to four sentences. Then either accept, by answering with the word ACCEPT and no tool call, or reject, by calling reject with your check, for example: from timespan import parse_span; assert parse_span("1h30m") == 5400
